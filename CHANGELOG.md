# Changelog

Notable changes to mathema are recorded here from its first public release onward.

## 0.6.2

### Upgrading from 0.6.1
- Record files under `.mathema/verified/` are named by a reversible encoding of their key, so keys with `/`, `:` or `#` save and load; existing files are renamed on the next write and old names are still read.
- `verify` lists only the functions it checked again or that have a problem, then the summary; `--verbose` lists every function as before, and `--format json` is unchanged.
- Sequences now meet the same-sign pair at the largest double, as scalars already did, so a claim over unbounded `R^n` whose code adds two such values is falsified on its computation line; bound the domain, or state `let |inf| be ...` to keep the float limit out of scope. The bundled rows this breaks are stated over `[-1e150, 1e150]^n`: `numpy.median` within range, `pandas.DataFrame.cumsum` columns, `pandas.Series.div` and `truediv` elementwise, and polars `rolling_mean` and `rolling_sum`.
- Clarity scores move once. A domain stated on the function (`@enforce_domain`, a guard to a set, `Literal`, a str `Enum`) is read as its domain, a claim is credited by the share of the function's inputs it covers (with a small floor, so any claim earns something), annotating a parameter never lowers a score, random-sampling evidence is graded by its number of draws, and a score of 100 means every source is settled by proof.
- Witnesses for missing and absent values are calls: `f(None) raises TypeError; f("ab") returns "AB"`, with any explanation on the next line.

### Soundness
- A raise at a missing value, or at a hazard input (empty, encoding, length, representation), counts against that input only when the same call with an ordinary value runs; otherwise the row is `unknown` and names the other argument.
- A falsification always rests on an executed witness at the claim's own point: a claim written at literal arguments (`f([]) == 0`, `f(nan) == 0`) is decided once at that call, a rounding miss in a numeric check no longer falsifies an exact identity, and installing z3 no longer moves a falsification off the mathematics line.
- Two functions are proven equal at the form step only from forms mathema computed itself.
- `f =:= g` with a side read by another frontend is answered by the equivalence family, or skipped with the reason `equivalence across runtimes needs the equivalence family` when none gives a verdict; the built-in steps compare two Python functions only.
- An annotated parameter is drawn as its annotation says (a `dict` in a module that imports numpy is drawn as a dict); a class mathema cannot draw is skipped with the reason; a claim's bound on a dataclass field or a table column bounds its draws; an empty pandas series is float like its draws.
- A `SystemExit` from the function is recorded as a raise with its exit code, and `mathema check` exits with its own code.
- `let` constants written by 0.6.0 read back as written, and a constant is recorded as its value (`let axis be 1`).
- The wall-clock cap also works off the main thread, so MCP tool calls are bounded; the claim parser reads a long run of digits in linear time.

### Languages
- A language can declare how a function refuses input outside it and what counts as its answer inside it (`Refusal`, `DefinedAnswer`); `excluded_outside_domain` and `is_language_defined` read them, and the record's language entry states them.
- Values removed with `\` count as outside draws, so `L[unicode] \ {""}` and `L[unicode, len >= 1]` agree.
- Runtime-type adapters may state their module aliases (`ALIASES`), and usage hints name every registered adapter; `rdd`, `na`, `write` and `sparkSession` are table attributes, not columns.
- The engine can read a function's body through an internal representation, so a body that arrives that way can be proven; facts injected on a callable are honoured everywhere mathema reads it, and a record names where such a body came from.

### Tools
- `@enforce_domain` with a plain set or list now enforces its values (it enforced nothing before); two numbers are the closed interval and a string uses the domain grammar (`"(0, 1]"`).
- `mathema check` and the MCP tools report a claim that does not parse, with the parser's message, and still check the function's other claims, as `verify` does.
- A suggested `raises(...)` row is bound to the region where the function's guard raises (`for x in (-oo, 0), raises(f(x), ValueError)`), and is left out when no region can be stated; it is no longer falsified at the inputs the guard admits.
- `mathema accept` refreshes the function's record, prints a shorter plan with the witness, and takes several claims at once (`accept KEY a b --as discovery`).
- `verify` reads each record and claims file once per run, so it no longer slows with the square of the store; `verify --format json` gives an invalidated row's reason and witness.
- `mathema verify` checks a function after the functions its claims' premises name, so a premise on another function's claim resolves on the first run; a cycle of such premises is reported as one.
- `mathema badges` finishes on large packages: one read per run, a cap on each function's step, progress on a terminal, a per-function result cache (`--refresh` recomputes everything), and `--jobs N` worker processes. Scores are unchanged.
- The `badges` MCP tool takes `implementation=false` to skip the coverage pass (implementation, overall and each function's implementation come back null), and reports the clarity algorithm version as `clarity_algo`.
- The effects line no longer reports non-mutating array methods (`Series.add`) as changing an argument.

## 0.6.1

### What a record now shows
- Mathematics and computation are separate lines: derive proves a claim over the reals, and the `[float]` companion and the probe show what the code does in float64, where a raise, a NaN from non-missing inputs or an infinity from a finite input is no value and fails every relation; the computation's infinity resolves at the claim (`let |inf| be`), the function (`pseudo_infinity:` in a claims file, `check(fn, pseudo_infinity=)`) or the project (`MATHEMA_PSEUDO_INFINITY`), else the float maximum.
- A claim's headline is falsified when any line under it is falsified, mathematics or computation, and otherwise it is the weakest line; a falsification on the mathematics line carries an exact witness checked independently of the solver that found it, or one certified by interval arithmetic where the point cannot be written exactly (`tan` at `pi/2`).
- One allowance governs every comparison of a computed result against the exact one (the probe, the `[float]` companion, the exhaustive sweep, a witness re-run, the exact re-check and `is_numerically_stable`), and its input-rounding part never exceeds the relative part of the result, so a float result of 0.0 for an exact 1.0 at inputs of 1e16 is falsified on the computation line; at such a miss the record names the condition number and says whether the loss is inherent to the inputs or the code's, offering a narrower domain or accepting the discovery.
- Every sequence and table column meets its magnitude corners on both routes, the opposite-sign pair at the largest double included, and a decimal literal in a claim is its exact written value on the mathematics line, never rounded.
- A domain renders what it admits, `[0.0, 1.0] : float|missing` in ASCII and `[0.0, 1.0] ⊂ ℝ ∪ {∅}` in unicode: a value is absent (`absent`, Python's `None`) when the object is not there, and missing (`missing`, `∅`) when one slot holds no computable value (`nan`, `NA`, `null`, `NaT`); a type clause states exactly what is admitted, and a binding without one is completed from the annotation.
- The record says in one sentence what the function did at each missing input (`at x = nan f gave nan back`, `at x = None f raised TypeError`), keeps in `meta["mathema.missing"]` the calls it made with the real value each word stands for (`None`, `nan`, `pd.NA`, each tried at least once, the degenerate containers first: empty, constant, length one, all-missing, a hole at the first and last position, a rank-deficient matrix), and counts draws as `(43 draws)` or `(257 entries across 57 draws, sizes (1, 1) to (8, 1))`.
- Every witness names its arguments (`x = nan, alpha = 0.5`), a large vector or matrix prints as its shape, first row and count, a string with invisible characters is followed by its escaped form, a record with a default repr shows its public fields, a witness too deep to print is summarised, and a recorded witness, one found by the exhaustive sweep included, is executed against the function and replays as the value that broke the claim.
- One `effects:` line under the function states what it writes or reads outside its arguments ("writes logs/app.log, reads os.environ", or "no side effects with default values"), and an automatic check mathema chose not to run leaves no row at all.
- Every remedy and "possible fixes" line puts its condition first and the claim or command last, after a colon ("(i) if nan for no data is intended, state: mean_ret([]) in {missing}").
- A lexicon row with an example function renders and round-trips as that function completes it (`for n in N` against `n: int` stays `N`), in `lexicon.show`, the golden snapshot and every `lexicon_problems` check; a row without one renders the unannotated default.

### Soundness
- A policy claim states what a function does with a value that is not there, `missing(f, x) propagates`, `absent(f, x) raises(TypeError)`, `missing(f, xs, null) drops`, with an optional premise (`assuming count(xs) >= 1, ...`); mathema writes one for every parameter that admits such a value and checks it, `mathema claims KEY` lists them, and `--write` puts them in `claims/policies.claims.yaml`.
- A value claim is judged wherever the function returns a value and never where it returns a missing value; a raise at a missing input that no claim accounts for, and a policy row the code contradicts, are falsified and fail `verify` and `check`, and `mathema accept KEY missing[x] --as discovery --corrected "..."` retires one with its witness.
- `is_missing_safe(f)` is about holes and `is_absent_safe(f)` about absence; a gate is proven only when every admitted member's policy comes from the code, a library's row, or a stated and confirmed claim, and an undeclared `None` return fails `is_absent_safe(f)`.
- Along a path, where the `None` sits decides the kind: a field or key holding `None` is absent (`null`), a key left out or an index past the end is absent (`unset`), a list element holding `None` is a hole (`null`); `\ {null}` and `\ {unset}` narrow a path binding, and a path has its own policy row (`absent(f, d.note, unset) drops`).
- The empty input is judged strictly: a `nan` or `None` returned for `[]` is no value and falsifies the claim's empty-input line unless the author states the intent with an ordinary claim (`f([]) in {missing}`, `raises(f([]), E)`, `f([]) == 0`) or guards it in the code, and a claim whose binding or premise excludes `[]` has no empty-input line.
- A value claim that binds no domain for a parameter is read over the working domain the function's own guards leave (a conditional raise, `@enforce_domain()`, `@enforce_dimensions()`), stated in the record's note, a literal passed in one call no longer pins that parameter for derive's domain, and a claim whose guards refuse every input is `unknown (no valid domain)`, never a vacuous `proven`.
- `is_representation_safe` judges an excluded spelling (`2.0` for `n: int`) on agreement with the in-domain value and with the declared return type, so a float returned where the function declares `-> int` falsifies it, with that as the stated reason.
- `=:=` says two functions are the same, so they agree where both give no value of one kind at the same input (`nan` and `nan`, `None` and `None`) and disagree where one gives a value and the other none; an absence agrees with an absence under `==` and `~=` too, an undeclared `None` return is the absence line's own finding, and a value claim against a value still treats a `nan` from present inputs as agreeing with nothing.
- A `raises(...)` claim over a finite domain is proven by calling the function at every point, two results compare by their values whatever their leaves are (so a filter that drops a row falsifies `f(xs) == xs` with a witness), and a bare `oo`, `inf`, `infinity` or `∞` is infinity on the probe route as well, so `f(x) < oo` on a finite function holds instead of being falsified at a random value.
- A `str` parameter has the type fact `: str` (`: str|absent` when it is `Optional`), a non-string is outside its domain, a bare check carries an `absent[p]` row for every `Optional` parameter, and the numeric families (representation, pole, number set, overflow, numerical stability) never run on a string, a bool or a kind they do not understand; before, a string with no stated domain was falsified on numbers drawn for it.
- `Literal[...]`, a `str` `Enum` and a guard to a set (`if side not in {"buy", "sell"}: raise`) read as the finite set `{"buy", "sell"}`, checked member by member and provable, a mixed function is split into one case per member, and an `Enum` parameter is called with its member and its spelling checked (`f("buy")` against `f(Side.BUY)`).
- Fixed: an integer result too large for a float is compared exactly (`f(n) == 2**n` over `[0, 2000]` is proven); a finite set with a missing value, a complex domain bound and a language with no member no longer raise out of a check; `Optional[str]` is read as a string parameter.

### Claims and grammar
- `a ~= b` means `abs(a - b) <= ε`, with `ε` the claim's declared tolerance or else 1e-9, decided exactly on the mathematics line and in float64 on the computation line; the record says how it read the claim, and a premise `assuming a ~= b` reads the same way.
- A pin is written in the call: `let alpha be 2, for x in R^n, f(x) == 2 * x[0]` reads `for x in R^n, f(x, alpha=2) == 2 * x[0]`, and the `let` form is still accepted as input.
- An `int` annotation completes a binding that states no type, so `for n in [0, 10]` on `n: int` is `for n in [0, 10] : int` on every route, and a type the claim states wins in either direction (`[0, 10] ⊂ R` widens, `: int` narrows).
- A dimension written as a number (`for A in R^(30,15)`, `for xs in [0, 1]^30`, `Mat(30, 15)`, `Vec(30)`, or mixed as `R^(n,15)`) is drawn at that size on every route, a value of another shape is outside the domain, `excluded_outside_domain(A)` tries every shape just outside the space, and the rows `shape` and `shape_enforced` are now `result_dimensions` and `dimensions_enforced`, with `size_enforced` new.
- A norm is written with double bars, `||x||`, `||x||_1`, `||x||_2`, `||x||_inf` (also `_oo`, `_∞`), `||x||_p` for a whole `p >= 1` and `||x||^2`, in unicode `‖x‖`, `‖x‖₂`, `‖x‖∞`; a claim keeps its bars in the claims file, is the same claim as the `norm(...)` spelling, and derive proves vector norms, lengths, distances and normalisations for every length.
- `sum`, `mean`, `std`, `var`, `min`, `max`, `prod`, `median`, `quantile`, `dot`, `cumsum`, `cumprod` and `count` in a claim read a vector's values with missing left out: over no value `sum` is 0, `prod` 1, `count` 0, `dot` and `norm` 0, the rest are missing, and `len` counts every position.
- Two relations, `in` and `not in` (`∈`, `∉`): `f(s) in L[slug]` holds every output to a language or a set, `"<" not in f(s)` says a value is never found in another, and `f(x) in [0, 1]` is the chain `0 <= f(x) <= 1`.
- The safety families answer three questions, does it run on my domain, is the answer right in float64, is it repeatable: `is_library_safe(numpy)` is definedness over a library's calls (`is_compendium_safe` is still read), `is_overflow_safe` and `is_recursion_safe` are new, `is_computation_safe(f)` and `is_repeatable(f)` roll them up, and `is_precision_safe`, `is_order_invariant`, `is_concurrency_safe`, `is_representation_consistent` and `is_memory_safe` are reserved and not decided in this release.
- A claim falsified only below some length is offered as a split: `mathema claims KEY --split "<claim>" --at "len(r) >= k"` writes the claim narrowed to the lengths where it holds beside the region row `is_defined` for those lengths, so what is known is recorded as a fact rather than a falsification to accept.
- Definedness is one tree: `is_defined` has `is_language_defined` (every member of a language input reaches a return; it absorbs `is_arbitrary_input_safe`) and `is_numerically_defined` with `is_pole_safe`, `is_number_set_safe` (was `is_builtin_safe`) and `is_dimension_safe`; `is_input_safe(f)` rolls up `is_missing_safe`, `is_absent_safe` and `is_empty_safe`; `@enforce_range()` checks a result and raises `RangeError`, a `ValueError`; every retired spelling still resolves and the record says so.
- `@enforce_domain()` enforces the policy rows (a `raises` row refuses the input with the exception it names, a `drops` or `propagates` row raises `MissingValueError`, a `DomainError`), and `@enforce_dimensions()` checks rank, fixed sizes and shared names at entry and the return marker at exit with a `ValueError` naming the parameter, the shape found and the shape expected.

### Libraries and compendia
- The wheel ships the bundled compendium; the 0.6.0 wheel carried none of it, so `is_compendium_safe(numpy)` was `unknown` and numpy calls counted as uncovered in the clarity score.
- A compendium is an ordinary claims file whose keys are a library's functions, with `compendium:` naming the library, `versions:` the installed versions it applies to (`"*"`, `">=X"`, `">=X,<Y"`, also per row) and optionally `aliases:`; a project's own file such as `claims/numpy.claims.yaml` merges with the bundled entry by row name (a project row replaces only the bundled row of the same name, the other bundled rows and guards still apply, and each row names its source), and the 0.6.0 compendium shape and `.mathema/compendium/` are gone.
- The bundled files cover `math`, 28 numpy functions (now with `divide`, `true_divide` and `reciprocal`), pandas and polars Series, each with its policy rows, and a runtime's missing values are definition rows under `defines:` (`missing := {null, nan}`, `absent := {Option::None}`), taken as axioms and never checked; `:=` is refused in a claim.
- A trusted `definition` row is an axiom: its mathematics is taken as stated and never caps a proof, while the computation line still runs the real library; the bundled rows are axioms from numpy 2.0, pandas 2.2 and polars 1.0 up and evidence below, a project's or third-party row is evidence (a proof through it caps at `holds`) until it is accepted with `mathema accept <key> <row> --as trusted`, only a `definition` row written with `==` is used as an axiom, and an acceptance goes stale when the row's statement is edited or its `versions:` range widened.
- A definition row is revoked as a wrong model only by a failure at an ordinary draw; a failure only at a magnitude corner, or a miss within what the row's own conditioning explains, is recorded on the row as a computation finding naming the draw, and the axiom stands; a bundled row that is not a definition and that only the float limit breaks is stated over `[-1e150, 1e150]^n` (`percentile` and `quantile` within range, `solve`, `diff`, `mul`, `pct_change`, `ewm_mean`).
- `mathema verify` checks the rows of every library function a project calls against the installed library, and a project's or third-party row gates the run until it holds locally or is accepted as trusted; `mathema verify <claims file>` checks every row of that file.
- `mathema compendium status` reports where the project stands with each library it calls, `update` pins the literal arguments the project's calls pass into rows of its own files, and `export <library>` writes a library's proven and held rows as a claims file for downstream projects, with the installed minor version as its range (`>=1.24,<1.25`) and a refusal to export bundled rows at or above the supported floor.

### Languages
- `for text in L[unicode], ...` quantifies a string parameter over a named language, stamped `grammar: mathema/language` (`𝕃[...]` is accepted); the names come from the `mathema-language` package (`pip install "mathema[language]"`) or a registered language, a claim naming a language no package serves is `unknown` with the reason "needs mathema-language", the probe visits every hazard of the language before any random member, and derive declines a string with the reason except over a finite language, which it sweeps.
- A length bound refines a language, `L[ascii, len <= 80]`, `L[unicode, len > 20]`, `L[unicode, len in [1, 80]]`, an `Annotated[str, MaxLen(80)]` parameter infers it, and any `key op n` refinement a package registers is served the same way.
- A binding names a path into a member at any depth (`o.address.zip`, `o.lines[0].sku`, `o.lines[*].qty`), rendered in the field's own type with its absence as `absent` and excluding a member where the path has no value, derive reads the numeric fields a body uses (`o.qty`, `o["qty"]`, `len(o.sku)`) so a claim over rows can reach `proven`, and a language may supply its own derive strategy.
- A string has no hole, so `Optional[str]` renders `L[unicode]|absent` with the package and `: str|absent` without it; over a language a length renders as `len(s)`, a witness shrinks inside the language in a few hundred checks, and an `excluded_outside_domain(s)` or `is_language_defined(s)` witness says whether it lies inside or outside the language in the language's own words.
- Extension points: the `mathema.languages`, `mathema.language_adaptors`, `mathema.language_refinements` and `mathema.lexicon` entry-point groups, the `languages`, `families` and `sampling` seams, and a family named `output_<slug>` contributing an output-contract predicate; the extension API version is unchanged.

### Tools and output
- `mathema claims KEY --suggest` offers `is_missing_safe(f)` and `is_absent_safe(f)` both and offers `is_numerically_stable` only for a number computed from numbers, `mathema describe` lists the edges just outside a passing domain that the computation rows know about, and `mathema --version` prints the installed version.
- The number of probe points is `trials=` in Python or `trials:` on a claim, which may raise the budget beyond the usual limits (a finite domain within it is swept in full on the computation line); `--trials-downscale` only shrinks it for development (`--trials-scale` is still read with a note), and the coverage line counts what was tried ("3,105 trials: 412 at discontinuities of ceil(100*active/periods), 7 edge cases, 2,686 random; the domain has 34,190 points").
- `check()` from Python notes when a project's compendium files were not read and names the call that reads them, `mathema.compendium.install(root)`.

### Compatibility
- `mathema verify` re-records, once, each claim whose written form these changes move, and says so once for the run: a pin written in the call, an `int`-annotated binding completed to `: int`, a string binding completed to `: str`, a definition row written with `==`, `is_numerically_stable`'s statement, a domain rendering the absent and missing values it admits, a language domain rendering absence, and a bare `oo` written `inf`.
- Every earlier spelling still reads: a record's `__mathema_missing__` sentinel reads as `missing` and is written as its word (`{"sentinel": "missing"}`), an older complex witness still replays, and `is_compendium_safe` resolves to `is_library_safe` with a note; clarity scores also move once, since the score now reads each call's hazard from the callee's own record and charges each parameter by what its domain leaves unknown (a type only, a bounded range, a narrower language, a finite set, an `Optional` absence), so the billing example's clarity goes from 29 to 34 and its overall score from 19 to 22 (`CLARITY_ALGO` entropy-dimensions@1.3).
- Python 3.10 to 3.14 are supported, and 3.15 is tested weekly as an early warning.
